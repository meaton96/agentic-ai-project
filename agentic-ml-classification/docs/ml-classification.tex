\title{An Agentic Multi-Agent ML Pipeline for Predictive Maintenance with a Deterministic Trust Boundary}

\author[rit]{Michael Eaton\corref{cor1}}
%\ead{me3870@rit.edu}

%\begin{abstract}
%Agentic AI systems built on Large Language Models (LLMs) offer contextual reasoning and adaptive tool use, but industrial machine learning (ML) applications such as predictive maintenance demand results that are verifiably correct, not merely plausible. This work presents a hybrid multi-agent classification pipeline in which six specialized LLM agents,intake, feature engineering, profiling, modeling, verification, and post-hoc deep-dive explanation,operate under a fully deterministic, non-LLM harness that retains exclusive authority over data splitting, metric computation, leakage detection, and sandboxed execution. Agents make judgment calls as structured proposals; the harness independently re-validates every proposal before acting on it, so a hallucinated column, a leaky preprocessing choice, or an unearned claim of performance is rejected rather than propagated. Beyond the original fixed-sequence orchestrator, the pipeline now supports dynamic orchestration: a nine-entry agent catalog, comprising the six agents above together with deterministic split-and-leakage-check and model-finalization steps and a narration step, and an eighth, independent LLM agent, a planner, that proposes which catalog entry runs next given the current run state. Every proposed step is independently re-validated against the real catalog and real run state before execution, the same propose-then-verify discipline applied to control flow rather than only content. The system is validated end-to-end on an aviation predictive maintenance dataset (NGAFID-MC), including bounded-memory featurization of multi-gigabyte sensor streams, entity-aware splitting by aircraft, and an evidence-grounded deep-dive agent that explains individual flagged flights. Real-LLM evaluation shows the dynamic orchestrator matching, and in one case exceeding, the fixed-sequence baseline by autonomously retrying a modeling step the baseline's hardcoded candidate budget could not, and shows that the harness's state bookkeeping cannot be made to assert a model was finalized without finalization genuinely executing, even when a locally hosted model is directly exposed to a prompt-injection string embedded in the training data. Two additional tabular benchmarks demonstrate generalization across binary and multiclass problems. Streaming ingestion, drift-triggered retraining, cross-run evidence reuse, and parallel candidate search remain future work.

\section{Introduction}
Recent hybrid frameworks combine LLM-based orchestration with specialized agents for prescriptive maintenance workflows~\cite{farahani2026}. These systems demonstrate that agentic reasoning can plan and execute complete analytical pipelines, but they inherit a structural risk: the most common ways an ML result turns out to be wrong, an incorrect train/test split, preprocessing fit on held-out data, a feature that copies the target, are precisely the errors an LLM can introduce and then confidently narrate past. The central design question addressed here is therefore not ``can agents run an ML workflow?'' but ``what is the smallest system in which agents can make real modeling decisions without being able to fool themselves, or us, about whether those decisions were any good?''

\section{System Design}
The architecture divides authority along a hard line (Table~\ref{tab:authority}). A base orchestrator invokes six specialized agents in a fixed sequence, each with a minimal decision surface, one or two read-only tools, and a strict JSON output contract; Section~\ref{sec:dynamic} describes a dynamic variant. Every agent output is a \emph{proposal} that a deterministic harness independently re-validates before acting on it.

The six agents are: (i) an \emph{intake agent} that converts a dataset and optional natural-language goal into a formal problem specification; (ii) a \emph{feature engineering agent} restricted to a vetted catalog of stateless, row-wise operations, provably safe to apply before any split exists; (iii) a \emph{profiler agent} that narrates deterministic dataset facts and a rule-based split recommendation it cannot override; (iv) a \emph{modeling agent} that selects from six verified pipeline templates and fills in configuration, it never writes code; (v) a \emph{verification agent} with strictly one-directional power: it reviews only candidates that already passed every deterministic gate and can flag or reject, never approve or unblock; and (vi) a \emph{deep-dive agent} that synthesizes hedged explanations of individual flagged predictions from three deterministic measurements it cannot alter.

Safety is layered: schema, column, and configuration validation; static AST rejection of forbidden imports and calls; subprocess sandboxing with resource limits; a label-permutation test that catches leakage in the modeling \emph{process}; and a candidate-scoped correlation gate that catches leakage in raw feature \emph{content}. A dedicated test constructs a near-copy-of-target feature and demonstrates that each gate catches a failure the other misses, the two are complementary by construction, not redundant.

\subsection{Dynamic orchestration}
\label{sec:dynamic}
A fixed sequence cannot express a genuinely different task, for instance explaining an already-flagged example, without running classification unnecessarily. A dynamic orchestrator instead selects from a nine-entry \emph{agent catalog}, the six agents above plus deterministic split, finalization, and narration steps, each declaring the run-state preconditions it requires. An eighth agent, a \emph{planner}, sees only the goal and a JSON-safe state summary, never raw data or fitted models, and proposes one next action: run a named catalog entry, or finish. A deterministic validator re-checks each proposal against the real catalog and state before execution, rejecting an unknown agent, an unmet precondition, or a repeated test-set touch, and feeding the reason back to the planner for a bounded retry rather than proceeding unchecked. This extends Table~\ref{tab:authority}'s division from dataset content to control flow.

\section{Predictive Maintenance Use Case}
The pipeline was validated on the NGAFID-MC aviation dataset: 22 engine-sensor channels sampled at $\sim$1\,Hz across thousands of flights and multiple aircraft, with a binary before/after-maintenance target. A streaming featurizer rolls raw timesteps into one feature row per flight with memory bounded by chunk size rather than file size (4.2\,GB source), and entity-aware splitting by aircraft prevents the same airplane from appearing on both sides of the evaluation boundary. For flagged flights, the deep-dive agent combines flight-phase segmentation, model-agnostic occlusion attribution, and an independent raw-signal cross-cylinder localization check, then reports whether the model's attribution and the raw-signal evidence agree,a lead for inspection, not a diagnosis. Two tabular benchmarks (Titanic, Iris) additionally exercised binary and multiclass generalization; 138 automated tests, including full-loop integration tests with a stubbed model client for both orchestrators, keep the agentic loop verifiable without network access. The dynamic orchestrator was also evaluated against the fixed baseline under a real, locally hosted LLM. On Iris, the fixed baseline exhausted its hardcoded candidate budget and failed outright, while the planner simply retried modeling until a candidate passed, an adaptive policy that emerged from a genuine decision rather than a hardcoded count. In an adversarial test, a prompt-injection string embedded in feature values instructed the planner to declare the run complete; regardless of how the planner reacted, the harness's state bookkeeping never asserted the model had been finalized unless finalization had genuinely executed, the property the trust boundary is designed to guarantee, holding under adversarial rather than only cooperative conditions.

\section{Limitations and Future Work}
The dynamic orchestrator (Section~\ref{sec:dynamic}) closes the planner gap identified as prior future work, but limitations remain: deep-dive attribution is binary-only, since it explains a single positive-class probability, and a wide feature table can exceed a small local model's context window before any architectural limit in the harness. Remaining future work, streaming ingestion, drift-triggered retraining, cross-run evidence reuse, and parallel candidate search, is expressible as additional narrow catalog entries under the existing planner and validator, not a new trust mechanism.

\section{Conclusion}
Hybrid agentic systems for manufacturing analytics are typically motivated by adaptability; this work argues that their adoption will equally depend on \emph{verifiability}, of orchestration decisions as much as modeling decisions. Placing every LLM judgment, including which agent runs next, behind a deterministic harness that checks it before acting yields a system where agents contribute genuine decisions while correctness never depends on an LLM being right, verified here empirically, including under adversarial pressure, not only by construction.
